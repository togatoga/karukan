# 文節

変換中に、文を文節ごとに直せます。変換結果の一部だけが違うとき、全体を打ち直さずに、その文節に移動して候補を選び直したり、文節の区切りを動かしたりできます。

```
きょうはいしゃにいく
  Space       →  今日は医者に行く        全体の候補一覧（これまでどおり）
  Ctrl+S      →  [今日は]医者に行く      文節に分かれ、最初の文節に注目
  →           →  今日は[医者に]行く
  Space       →  今日は[慰謝に]行く      注目中の文節だけ次の候補へ
  Enter       →  全体を確定
```

## キー

| キー | 動作 |
|------|------|
| Ctrl+S | 文節に分ける。もう一度押すと別の区切り方に切り替える（[区切り方](#区切り方を切り替える)） |
| ← / → （Ctrl+B / Ctrl+F） | 注目する文節を移動。端では反対側の端に回る |
| Home / End （Ctrl+A / Ctrl+E） | 最初 / 最後の文節に移動 |
| Shift+← / Shift+→ | 注目中の文節を1文字縮める / 伸ばす |
| Space / ↓ / ↑ など | 注目中の文節の候補を選ぶ |
| Ctrl+1〜9 | 注目中の文節の候補を番号で選び、次の文節へ進む |
| F6〜F8 / Ctrl+K | 注目中の文節だけをひらがな / カタカナ / 半角カタカナにする |
| Ctrl+T / Ctrl+R / Ctrl+I | 注目中の文節の候補をソース別に絞り込む |
| Enter | すべての文節をまとめて確定 |
| Escape / Backspace | 変換をやめて入力編集に戻る |
| 文字キー | 表示中の内容を確定して、次の入力を始める |

Space を押した直後は、これまでどおり全体がひとつの文節です。候補一覧も全体に対するもので、AIの別候補（ビームサーチの結果）や学習履歴・辞書の語句がそのまま並びます。

**文節に分けるのは Ctrl+S を押したときです。** そのとき選択中の候補（AI・学習履歴・辞書のどれでも）が文節に分かれ、最初の文節に注目します。表示される文字列は分ける前と変わりません。

入力中（ライブ変換中）に Ctrl+S を押すと、変換を開始して、**画面に出ていたライブ変換の文字列**を文節に分けます。Space の変換は学習履歴の候補を先頭にしますが、Ctrl+S はそちらではなく、見えていた文字列を分けます（学習履歴の候補は一覧に残っています）。

矢印キーでも分けられます。全体のまま → を押すと2番目の文節、← を押すと最後の文節に注目します（Home / End は最初 / 最後、Shift+← / Shift+→ は最初の文節を伸縮）。

1語だけの変換（きょう → 今日）は分かれないので、押しても何も起きません。全体（1文節）に戻るには、Ctrl+S を全体になるまで押します。

### 区切り方を切り替える

区切り方は3通りあります。Ctrl+S を押すたびに次の区切り方に切り替わります。最後の区切り方の次は、分ける前の全体（1文節）に戻り、もう一度押すと最初の区切り方になります。

```
全体 → 辞書(最長) → 字種 → 辞書(最短) → 全体 → …
```

| 補助行の表示 | 区切り方 | 競技プログラミングを学ぶ |
|---|---|---|
| 辞書(最長) | 辞書の語で、文節の数がいちばん少なくなるように切る。1文字のひらがなの語は前の語に付ける | 競技プログラミングを｜学ぶ |
| 字種 | 字種（漢字・ひらがな・カタカナ・英数字）が切り替わるところで切る | 競技｜プログラミング｜を｜学｜ぶ |
| 辞書(最短) | 辞書の語で、文節の数がいちばん多くなるように切る | 競技｜プログラミング｜を｜学ぶ |

- 最初の Ctrl+S と矢印キーは、辞書(最長) で分けます
- 前の区切り方と同じ結果になるものは飛ばします。3通りとも同じなら、Ctrl+S はその区切り方と全体を行き来します
- 全体に戻ったとき、文節で選び直した表記はそのまま残り、全体の候補一覧の先頭になります
- デバッグモードでは、切り替えられるときに補助行の末尾へいまの区切り方を `区切り:字種` のように出します
- 切り替えても表示される文字列は変わりません。文節で選び直した表記もそのまま引き継がれます
- どの区切り方でも、必ず2つ以上に分かれます。全体が辞書の1語のとき（競技プログラミング）は、辞書(最長) でもそれを作っている語に分かれます（競技｜プログラミング）
- 細かい調整は Shift+← / Shift+→ で文節を伸縮します

辞書の2つは、辞書にある語を文節にします。辞書にないひらがな（活用語尾など）は前の語に付きます。

辞書(最長) には規則が1つだけあります。**1文字のひらがなの語（を・は・に など）は、前の語に付けます**（今日は｜医者に｜行く、学校には｜行く）。辞書には品詞がないので助詞かどうかは分かりませんが、1文字のひらがなが単独で語になるのは、ほとんどが助詞だからです。2文字以上のひらがなの語（から・まで）は付けません（東京｜から｜来た）。辞書(最短) にはこの規則がないので、助詞だけを離したいときは辞書(最短) に切り替えます。

字種は、字種が切り替わるところだけで切ります。語かどうかは見ないので、送り仮名も離れます（学｜ぶ）。

辞書(最短) は極端な区切り方です。辞書の語で埋められるかぎり、どこまでも細かく割ります。長い語が部品に分かれる（早稲田｜大学）だけでなく、1文字の語にもなり（東｜京）、意味に関係なく割れることもあります（プログラミング → プロ｜グラ｜ミング）。歯止めは入れていません。どこで切りたいかは使う人が決めることで、こちらで候補を狭めないためです。

### どの文節に注目しているか

注目中の文節は、入力中の文字列の上では太い下線（macOS では選択範囲としても）で示します。補助行には、注目中の文節の読みだけを出します。

ターミナルなど、下線を描き分けないアプリでは注目位置が見分けられません。その場合はデバッグモード（「でばっぐもーど」を変換して切り替え）にすると、補助行に区切りと注目位置が出ます。

```
今日は[医者に]行く いしゃに 文節2/3 区切り:辞書(最長)
```

`[ ]` が注目中の文節、その後ろが文節の読みと位置、切り替えられるときは区切り方です。文が長いときは両隣の文節だけを出し、それより先は `…` で省略します。

変換を解いて入力編集に戻るには Escape か Backspace を使います（以前は ← → でも戻りましたが、文節の移動に変わりました）。英字の直接入力と絵文字入力には文節がないので、そこでは ← → は従来どおり編集に戻ります。

## 文節の伸縮

Shift+← / Shift+→ は、注目中の文節の右端を読み1文字ぶん動かします。

```
[今日は]医者に行く
  Shift+←  →  [今日]歯医者に行く
```

- 注目中の文節は、新しい読みから変換し直されます
- その後ろは、まとめて変換し直してから文節に分け直されます。前の文節が変わると続きの読まれ方も変わるためです
- 注目中の文節より前は、そのまま残ります

## 学習

文節に分かれた変換を確定すると、2種類が学習されます。

- **文全体**: 「全体の読み → 確定した文字列」。これまでの確定と同じです。文節をどう切ったかに関係なく、読みを全部つなげれば打った読み、表記を全部つなげれば確定した文字列なので、この対は常に正確です（`max_surface_chars` を超える長い文は従来どおり記録されません）
- **文節ごと**: 「文節の読み → 選んだ表記」。注目して候補一覧を出した文節だけが対象です。次に同じ語が別の文で出たときに効きます

一度も注目しなかった文節は、文節単位では学習されません。全体の変換結果から切り出しただけで、読みとの対応が推測だからです。

学習データの形式は変わりません。エントリはもともと「読み全体 → 表記」で保存されていて、途中まで打って予測で出た学習候補も、そのエントリ自身の読み全体を持っています。文節に分けるときは、その読みと表記を対応付けます。

## 文節の求め方

karukan は形態素解析をしません。連接コストも単語コストも持たず、ラティスも組みません。モデルは読みを受け取って変換結果を返すだけで、どの部分がどの読みから来たかは教えてくれません。

あるのは辞書と、同じ文を表す2つの文字列（入力したかなと、変換結果）です。そこで、**入力したかなと変換結果の文字列を対応付ける問題**として文節を求めます。

### 1. かなと変換結果を対応付ける（辞書の最長一致）

変換結果を左から順に、次の3種類の単位で覆います。それぞれが読みの一部を引き受けます。

```
読み      き ょ う は い し ゃ に い く
変換結果  今日    は 医者    に 行く
          辞書語  字 辞書語  字 辞書語
          きょう  は いしゃ  に いく
```

| 単位 | 内容 |
|------|------|
| 辞書の語 | 読みのその位置から始まる辞書の語で、表記が変換結果の同じ位置にあるもの |
| 同じ文字 | 変換結果の1文字 ↔ 読みの同じ1文字。辞書の語に入らなかったかなや、数字のまま打った数字（カタカナはひらがなに、全角英数は半角に揃えて比べる） |
| 辞書にない語 | かなでない文字の並び ↔ 読みの1文字以上 |

覆い方はたくさんありますが、選ぶ基準は次の順です。

1. 辞書の語に入らなかった文字が、いちばん少ないもの（記号は数えません）
2. その中で、辞書にない語の数がいちばん少ないもの
3. その中で、語の数がいちばん少ないもの
4. その中で、文節の数がいちばん少ないもの。ただし2つ以上

つまり「できるだけ辞書の語で、できるだけ少ない語数で覆う」で、これが辞書の最長一致です。基準3があるので、「です」は「で」と「す」の2語ではなく1語として使われます（辞書には、ほぼすべてのかな1文字が語として載っています）。語ごとの点数や、連接コストのようなものはありません。動的計画法で求めます。

4 に「2つ以上」とあるのは、全体が辞書の1語のとき（競技プログラミング）に、次に文節が少ない覆い方（競技｜プログラミング）を採るためです。そのために、覆い方をいくつか順位付きで求めています。文節の数が同じ覆い方が複数あるときは、決め手がありません。

基準1があるので、辞書にある語は必ず語として使われます。「から」が辞書にあれば、前の語に付けるより「から」を1語とするほうが、辞書の外に残る文字が少ないからです。

そのうえで、1文字のひらがなの語だけは文節の頭にせず、前の語に付けます。辞書の最長一致に足している規則は、これ1つです。

- **最長一致**: 同じ範囲なら、短い語2つより長い語1つが選ばれます（東｜京 ではなく 東京）
- **消去法**: 辞書にない語は、両隣が辞書の語やかなで決まれば、間に残った読みがその語の読みです（上司｜忖度｜部下 で 忖度 が辞書になくても、そんたく が割り当たります）
- **カタカナ語**も辞書の語として扱います（テスト｜ケース）

システム辞書とユーザー辞書の両方を使います。

### 2. 対応付けに失敗したら分けない

変換結果が読みの変換として成り立っていないときは、全体をひとつの文節のままにします。間違った対応のまま分けるより安全だからです。

- **かなが合わない**: モデルがかなを書き換えた場合（こんにちわ → こんにちは）は、対応付けそのものができません
- **読みを落とした**: 「わせだにだいがく → 早稲田大学」のようにモデルが読みの一部を落とすと、余った「に」は隣の漢字の読みに吸われてしまい、対応付け自体は成立します。そこで辞書と照合します。大学 は辞書では「だいがく」なのに「にだいがく」が割り当たった、という食い違いがあれば失敗とみなします
- **長すぎる**: 120文字を超える読みは対応付けを行いません

辞書にない語で起きた読み落としは検出できません。その場合は余ったかなが隣の文節の読みに入りますが、その文節に注目すると補助行に読みが出るので、ずれていることは見て分かります。

### 3. 切れ目を決める

**語の頭が切れ目です。** 語とは、辞書の語と、消去法で決まった辞書にない語のことです。「ご存知」のように途中で字種が変わる語も、辞書の1語なら1単位で、その途中で切ることはありません。

辞書だけでは決まらないところが2つあり、そこだけ字種を見ます。

- **辞書にないカタカナ・英数字の並びは1語とみなす**（辞書にない プログラミング や Claude）
- **どの語にも入らなかったひらがなと記号は、前の語に付ける**

辞書には品詞がないので、「は」「に」（助詞）と「これ」「ここ」（語）を辞書からは区別できません。そこで文字数で分けています。1文字のひらがなの語は前の語に付け、2文字以上の語は文節にします（これは｜ここに｜ある、今日は｜医者に｜行く）。

### 3つの区切り方の違い

ここまでが **辞書(最長)** です。ほかの2つは、同じ対応付けの求め方で、基準だけを変えたものです。

- **辞書(最短)**: 基準3と4を「文節の数がいちばん多いもの」に変えます。1文字のひらがなを前の語に付ける規則もなく、辞書の語だけで決まります（今日｜は｜医者｜に｜行く）
- **字種**: 切る場所を字種だけで決めます。漢字・ひらがな・カタカナ・英数字が切り替わるところがすべて切れ目で、ほかの規則はありません。助詞や接頭語、送り仮名といったことは考えないので、「学ぶ」は 学｜ぶ、「お茶」は お｜茶 になります。記号と長音「ー」は字種を持たないので、前の文字に付きます。辞書は切る場所には関わらず、各文節の読みを決めるための対応付けにだけ使います

分かれなかったところや、切れ目がずれたところは Shift+← / Shift+→ で直してください。

### 4. 文節ごとに変換する

分けた直後の各文節の表記は、全体の変換結果から切り出したものです。分けるために変換し直すことはないので、分かれても表示は変わりません。

文節に初めて注目したとき、その文節の読みだけで候補一覧を作ります。左文脈は、エディタの文脈にそれより前の文節の表記を足したものです。ライブ変換が Chunk ごとに変換するのと同じ仕組みで、区切りを自分で動かせる点が違います。切り出した表記が一覧の先頭に来るので、注目しただけで表示が変わることはありません。

文節の読みは固定なので、文節の候補には、読みがそれより長い語（予測変換の候補）は出ません。

## 制限

- 文節に分かれている間は、F9 / F10（英数への変換）は使えません。その範囲を打ったキーを記録していないためです
- 文節に分かれている間は、Ctrl+J（Chunk の区切り）は使えません
